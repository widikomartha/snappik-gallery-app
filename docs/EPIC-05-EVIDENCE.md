## Delivered boundary

Client review confirms exactly the acknowledged shared revision into an immutable database snapshot and locks editing. Matching main-session/key/body retries recover the original confirmation; concurrent saves/confirms cannot overwrite acknowledged data. Owner result/history views, copy and CSV distinguish current draft from immutable confirmation revisions. Reopen requires active entitlement, current revision and a reason; it retains choices/history, increments revision and audits atomically. ID/EN interfaces pause editing after uncertain confirmation/reopen and reuse the same request for recovery.

Original delivery resolves only published in-project IDs under a separate current download grant. Selection/confirmation is independent. Public source reads validate ancestry/version before and after transfer; current grant/source-pointer checks repeat before bytes. The local implementation validates one complete bounded original before attachment headers, checks actual content signature/exact length and never persists originals. Limits are 50 MiB, 60 seconds including validation and two originals/process. The browser waits for a complete body before offering a file. This establishes local failure behavior, not hosted transfer capacity.
